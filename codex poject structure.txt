Yes, it is possible.
Recommended architecture:
Chrome History DB
        ↓
Spring Boot Backend
        ↓
Validation + Tagging + Calculations
        ↓

How it would work:
1. Fetch browser history
   - Chrome stores history in a local SQLite file.
   - Backend copies the Chrome History file.
   - Then it reads URLs, titles, visit counts, and timestamps from SQLite.
2. Validate data
   - Check valid URL format.
   - Skip empty URLs/titles.
   - Ignore duplicate records.
   - Validate timestamp and domain.
3. Tag URLs
   - Match URL/title/domain against keyword rules.
   - Example tags:
     - search
     - coding
     - learning
     - job-search
     - social
     - entertainment
     - shopping
     - ai-tools
4. Calculate insights
   - Most visited domains.
   - Visits by category.
   - Browsing by date/time.
   - Productive vs non-productive usage.
   - Daily/weekly trends.
5. Save to backend database
   - Store processed records in MySQL.
   - React frontend calls Spring Boot APIs to show charts and tables.
For dependencies, use:
Spring Web
Spring Data JPA
MySQL Driver
SQLite JDBC
Validation
Lombok
DevTools
Spring Boot Starter Test
Spring Security is not required for a local/personal dashboard.
But if you deploy it online or make it multi-user, then add Spring Security later. For now, since this is a local Chrome-history analysis project, you can skip it.
Important note: automatic fetching works only if the backend runs on the same machine where Chrome history exists. A normal browser plugin or React frontend cannot directly read Chrome’s full history unless it is built as a Chrome Extension with the history permission.

Yes, but with an important clarification:
A Spring Boot app itself cannot be installed as a Chrome plugin. The correct architecture would be:
Chrome Extension
        ↓
User grants browser history permission
        ↓
Extension reads Chrome history
        ↓
Sends data to Spring Boot backend
        ↓
Backend validates, tags, calculates insights
        ↓
React dashboard displays results
So every end user can use it only if:
1. They install your Chrome Extension.
2. They explicitly allow the extension’s required permissions, especially browser history access.
3. Your extension is approved/distributed through the Chrome Web Store, or installed manually in developer mode.
4. Your Spring Boot backend is available either locally or on a hosted server.
5. Your app handles user accounts/data separation properly if multiple users use it.
Spring Security is useful for the backend, but it does not grant Chrome history access. Chrome history access is controlled by the Chrome Extension permission system.
Recommended structure:
chrome-history-extension/
  manifest.json
  background.js
  popup.html
  popup.js

springboot-history-backend/
  REST APIs
  validation
  tagging logic
  MySQL storage
  Spring Security optional/needed for accounts

react-dashboard/
  charts
  filters
  insights
For a public/multi-user product, use Spring Security. For a local personal project, it is optional.
Short answer: Yes, end users can access it, but they need to install the Chrome Extension and grant history permission. Spring Security protects your backend, while Chrome permissions control browser-history access.
